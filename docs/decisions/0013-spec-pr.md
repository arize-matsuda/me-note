# 0013: 仕様は issue を作る前に PR で main に入れる

- 日付: 2026-11-18
- 状態: 採用

## 背景

仕様は `docs/features/<機能名>.md` に書き、親 issue からリンクする（[0006](0006-issue-workflow.md)）。
しかし、仕様のファイルをいつ main に入れるかが決まっていなかった。main に入っていないと、親 issue からのリンク先が見つからない。

## 決定

- **`/spec` で仕様を確認済みにしたら、仕様だけの PR を作る**
- ブランチ名は `docs-<短い英語名>-spec`（例: `docs-weight-spec`）。issue がまだないため、[0007](0007-branch-and-pr.md) の「issue がない作業」の名前の付け方に従う
- issue（`/issues`）は、仕様の PR がマージされる前に作ってもよい。リンクはマージ後に開けるようになる
- 実装中に仕様を直す必要が出たら、そのサブ issue の PR で一緒に直す

## 理由

- 仕様と実装を別の PR にすると、仕様の確認と実装の確認を分けて行える
- 仕様が先に main に入るため、親 issue のリンクが常に main の最新の仕様を指す
