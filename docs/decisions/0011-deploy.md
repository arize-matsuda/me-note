# 0011: Vercel への公開

- 日付: 2026-11-17
- 状態: 採用

## 背景

web を Vercel に公開する（[0003](0003-hosting-database-auth.md)）。
デプロイのきっかけ、PR ごとの確認方法、本番 DB へのマイグレーションの適用方法、実行地域、URL を決める必要がある。

## 決定

### デプロイのきっかけ

- **Vercel と GitHub を連携する**。main にマージすると、自動で本番に反映される
- Vercel のプロジェクトの Root Directory は `web`

### PR ごとのプレビュー

- **PR ごとにプレビュー（専用の URL）を作る**。AI が作った PR を、スマホから触って確認してから承認できる
- **プレビューは開発用 DB（Neon の `dev` ブランチ）を使う**
- プレビューの URL は PR ごとに変わるため、プレビューのときだけ、そのデプロイの URL（Vercel が自動で設定する `VERCEL_URL` と `VERCEL_BRANCH_URL`）をログインで許可する（`web/src/shared/auth/server.ts`）。`*.vercel.app` のようなワイルドカードは使わない

### 本番 DB へのマイグレーション

- **本番デプロイのときに、ビルドの前に `pnpm db:migrate` を実行する**（`web/vercel.json` の `buildCommand`）
- プレビューでは実行しない（`VERCEL_ENV` が `production` のときだけ）
- マイグレーションが失敗したら、ビルドも止まり、前の版が公開されたままになる

### 実行地域

- **アプリを動かす地域はシンガポール（`sin1`）**。DB と同じ地域にする（[0009](0009-database.md)）
- `web/vercel.json` の `regions` に書く。ビルドが行われる地域は変わらないが、問題ない

### URL

- **Vercel が用意する URL（`○○.vercel.app`）を使う**。独自ドメインは必要になったら追加する

### 環境変数

Vercel の管理画面（Settings → Environment Variables）で設定する。値はリポジトリに入れない。

| 名前 | Production | Preview |
|---|---|---|
| `DATABASE_URL` | Neon の `production` ブランチ | Neon の `dev` ブランチ |
| `BETTER_AUTH_SECRET` | 本番用の値 | 本番・手元とは別の値 |
| `BETTER_AUTH_URL` | 本番の URL | 設定しない |

## 理由

- GitHub と連携すると、手作業でのデプロイが不要になり、「PR を承認してマージするだけ」で本番に反映できる
- プレビューがあれば、手元で開発サーバーを動かさなくても、変更を画面で確認できる。開発用 DB を使うので、本番のデータを壊さない
- マイグレーションをデプロイに組み込むと、適用し忘れがない。本番 DB の接続文字列を手元に置く必要もない
- アプリと DB の地域をそろえると、DB への問い合わせが速くなる
- 設定をファイルに書くと、変更が PR でレビューできる

## 注意

- Vercel のプレビューには、最初から保護（Vercel Authentication）がかかっている。開くには Vercel へのログインが必要
- マイグレーションは本番デプロイで初めて実行されるため、プレビューでは本番 DB への適用を確かめられない。テーブルを消す・名前を変えるなど、データを失う変更は PR で特に注意して確認する
- マイグレーションの適用後にビルドが失敗すると、DB は新しく、公開中のアプリは古いままになる。テーブルの変更は、古いアプリでも動く形（列の追加など）を基本にする
